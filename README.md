# Agent Guild（エージェントギルド）

AIを使う前提を**掲載者が明示する**OSS Issue掲示板です。既定は報奨金・支払のない**無料版**で、依頼者・回答者とも無料です。社内向けには [公開手順](docs/deploy.md) で、IP 制限と GitHub 組織メンバーのログインを付けて公開できます。GitHubの公開Issueを参照し、達成条件、AI利用方針の根拠、元Issueへのリンクを掲載します。UIは日本語中心の「クエストボード」ですが、実際の開発に必要な情報を優先しています。

## 起動

Node.js 22.18以上が必要です。組み込みの `node:sqlite` を使用するため、この Node.js 版では実験的機能の警告が表示されます。

```bash
npm install
npm run build
npm run server
```

`http://127.0.0.1:46077` を開きます。開発中は別ターミナルで `npm run dev`（通常 `http://127.0.0.1:5173`）を起動できます。ViteはAPIをローカルサーバーに転送します。

```bash
npm run lint
npm test
```

## GitHub ログインのローカル設定

書き込みには GitHub ログインが必要です。既存の GitHub OAuth App を利用する場合だけ、`AGENT_GUILD_GITHUB_CLIENT_ID` と `AGENT_GUILD_GITHUB_CLIENT_SECRET` をサーバーの環境変数で設定し、コールバック URL を `http://127.0.0.1:46077/api/auth/callback` に合わせてください。ポートや公開元を変える場合は `AGENT_GUILD_ORIGIN` にその origin を設定します。資格情報をリポジトリや `data/` に保存しないでください。この開発作業では資格情報の新規発行や実アカウント接続は行っていません。

OAuth は公開プロフィールの利用者 ID とログイン名だけを取得し、`AGENT_GUILD_GITHUB_ORG` を設定した場合だけ組織メンバーの確認に `read:org` を要求します。ログイン開始ごとの state と一時 Cookie に加え、PKCE S256 の challenge/verifier を照合して認可コードを交換します。アクセストークンは本人確認後に破棄します。サーバー側のセッションはメモリに保持され、8時間で期限切れになり、サーバー再起動時にも失効します。Cookie は HttpOnly / SameSite=Lax で、HTTPS origin では Secure が付きます。書き込みは CSRF トークンで確認します。

開発時に `npm run dev` の Vite 画面（`http://127.0.0.1:5173`）を使う場合、そのローカル origin からの書き込みも CSRF 確認後に受け付けます。OAuth コールバック後は API サーバーの画面に戻るため、Vite の画面を使い続ける場合は `http://127.0.0.1:5173` を開き直してください。HTTPS の origin ではこのローカル開発用例外は適用しません。

設定がない場合も一覧は閲覧できますが、ログイン開始は利用できず、API の書き込みは拒否されます。画面はログインした GitHub 利用者と掲載の所有者に応じて操作を表示します。API は GitHub の利用者 ID に基づき、新規掲載の検収・取消を掲載者本人に、新規回答とウォレット公開アドレスを回答者本人に結び付けます。旧 JSON から移行した掲載・回答は所有者不明として読み取り専用にし、既存の共用デモアドレスを誰にも自動割当てしません。社外への公開運用には使えません。社内向けの公開は次の節の設定で行います。

## 無料版と社内公開の設定

| 環境変数 | 既定 | 内容 |
| --- | --- | --- |
| `AGENT_GUILD_GITHUB_ORG` | なし | 設定すると、この GitHub 組織の有効なメンバーだけがログインでき、閲覧を含む全ページでログインが必要になる。SAML SSO の組織では初回に SSO の認可を求められる。 |
| `AGENT_GUILD_REQUIRE_LOGIN` | なし | `1` で、組織を指定せずに全ページのログインを必須にする。 |
| `AGENT_GUILD_DEMO_REWARDS` | なし | `1` のときだけ、模擬 USDC 報奨金とウォレット登録を有効にする（開発・デモ用）。既定の無料版では、報奨金付きの掲載とウォレット登録を拒否し、画面にも出さない。 |

IP 制限、HTTPS、日次バックアップを含む VM での公開手順は [docs/deploy.md](docs/deploy.md) にあります。

## できること

- Issue一覧、キーワード・言語・ラベル・状態での絞り込み、詳細、GitHubの元Issueへの導線
- `https://github.com/owner/repo/issues/番号` に限定した公開GitHub API参照、取得失敗・不正URL・Pull Request混入・重複URLの検査
- 掲載者のAI利用申告と根拠、maintainer承認の**未検証の申告**を区別した表示。デモ見本はAI利用未確認と明記
- GitHubログイン（要設定）と所有者に応じた操作表示、回答者の作業開始・納品、掲載者が複数の回答から1件を選ぶ検収
- （`AGENT_GUILD_DEMO_REWARDS=1` のときだけ）任意のUSDC額、デモ用公開ウォレットアドレス、検収後の模擬支払、失敗と取消の履歴、二重支払防止

デモ見本は実募集ではありません。外部OSSのmaintainerがAI利用を許可したと推定しません。フォーム上の掲載者申告は maintainer 承認の証明ではありません。掲載と同じ Issue の公開コメント URL は存在と本文の変更を再確認できますが、コメント内容が AI 利用を許可するかは自動判定しません。GitHub API情報は掲載時のスナップショットで、元 Issue の現況は画面から個別に照会します。

## データと境界

入力した掲載、回答、ウォレット**公開アドレス**、支払状態はローカルの SQLite `data/listings.sqlite`（schema version 2）に保存されます。更新はトランザクションで確定し、同じ DB を使う複数プロセスでも更新ごとに最新状態を読み直します。DB、SQLite の補助ファイル、バックアップは `data/` ごと Git 管理対象外です。本番 DB・公開運用としての負荷や復旧は未検証です。ローカルAPIは127.0.0.1にバインドします。GitHubログインのコードとセッションがあり、新規掲載と回答の所有者を API で確認します。旧データは本人へ割り当てず読み取り専用です。社外公開に必要な監査運用・乱用対策の強化等は未完成のため、社外公開や社外からの投稿には使えません。秘密鍵・ウォレット生成・署名は扱いません。

### 旧 JSON からの移行と復旧

旧版の `data/listings.json` があり、SQLite DB がまだない場合、初回起動時に全件を一時 DB へ取り込みます。ID、回答、報奨金履歴、旧デモ用公開アドレスを保持し、成功後に `data/listings.json.backup-...` を作って DB を配置します。JSON 原本も残し、再起動時には再移行しません。移行に失敗した場合は DB を配置せず、JSON 原本を変更しません。

移行した共用デモアドレスは保存されますが、新しいログイン利用者のアドレスとして扱いません。利用者ごとに公開アドレスを登録し直してください。

復旧時はサーバーを止めて `data/` 全体を別の場所へコピーしてください。DB に問題がある場合は `listings.sqlite` とその `-wal` / `-shm` を別の場所に退避し、元の JSON またはバックアップを `data/listings.json` として確認してから再起動すると、初回移行をやり直せます。DB 作成後の変更は古い JSON には反映されないため、古い JSON に戻すとその変更は失われます。既存データを削除せず、必ずコピーで確認してください。

停止時バックアップ、隔離復元、切り戻し時の確認順は [復旧手順案](docs/offline-recovery.md) にまとめています。合成データの訓練のみ確認済みで、実環境の復旧手順や復旧目標は未承認です。

### 投稿制限と通報

新規掲載と回答は、ログイン利用者ごとに初期値で **60秒あたり5件** までです。ローカル環境変数 `AGENT_GUILD_POST_LIMIT`（1〜100）と `AGENT_GUILD_POST_WINDOW_MS`（1000〜86400000）で変更できます。上限を超えた投稿は HTTP 429 で保存しません。

ログイン利用者は掲載または回答を理由付きで通報できます。同じ対象への重複通報は拒否し、通報も利用者ごとに同じ時間枠の件数上限を適用します。通報と管理者操作の履歴は SQLite に保存されます。`AGENT_GUILD_ADMIN_IDS` に管理者の GitHub 数値 ID をカンマ区切りで設定した場合だけ、`GET /api/moderation` で通報を確認し、`POST /api/moderation/:listingId` に `{"action":"hide","reason":"..."}` または `{"action":"restore","reason":"..."}` を送れます。操作にはログインセッション、CSRF token、10〜500文字の理由が必要です。未設定時は管理者なしです。一般利用者の管理者操作は拒否され、非表示の掲載は一般一覧と詳細から除外されます。誤判定は restore で戻せます。これはローカル試作の運用停止手段であり、公開運用を許可するものではありません。

### 模擬支払

既定の無料版では無効です。`AGENT_GUILD_DEMO_REWARDS=1` のときだけ動きます。USDCの報奨金は状態遷移だけの**sandbox/demo**です。資金預託、決済、実送金、チェーン接続は一切ありません。支払確定条件は仮仕様として「掲載者による検収」です。失敗後は公開アドレス登録後に再試行でき、支払済み・取消済みは再支払できません。同時送信と再送で競合した操作は 409 を返し、報奨金履歴を二重に追加しません。現実の支払可否は判断していません。

| 現在の状態 | 操作 | 結果 |
| --- | --- | --- |
| 待機中 | 回答を指定して検収 | アドレス登録済みなら模擬支払済み、未登録なら失敗 |
| 失敗 | 同じ回答を再検収 | アドレス登録済みなら模擬支払済み、未登録なら 409 |
| 待機中・失敗 | 取消 | 取消済み |
| 模擬支払済み・取消済み | 検収・取消 | 409、状態不変 |

SQLite の監査表には検収・取消の操作者 ID、掲載 ID、操作、時刻、適用または拒否の結果だけを記録します。セッション Cookie、OAuth token、ウォレットアドレスは記録しません。既存 schema v1 は起動時に v2 へ移行します。

本番化には認証と権限、GitHub maintainer承認内容の人による判断と失効対応、本番向けの監査運用と復旧、スパム対策、チェーン・トークン、鍵管理、アップグレード権限、返金権限、検収主体、送金provider、KYC/法務と資金管理のレビューが必要です。Stripeの[stablecoin payouts](https://docs.stripe.com/connect/stablecoin-payouts)は現時点で米国プラットフォーム限定のprivate previewで、日本向けUSDC送金手段として採用済みではありません。資金移動に関する判断は[金融庁FAQ](https://www.fsa.go.jp/news/27/sonota/20151214-2.html)等を踏まえた専門レビューが必要で、無料・OSS・自己管理だけを理由に登録不要とは判断していません。
