### PKCE の検証

[GitHub OAuth Web application flow の公式仕様](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps)は `code_challenge`、`code_challenge_method=S256`、`code_verifier` を強く推奨する。公開 `main` `124fef9` の `server/auth.mjs` は state と一時 cookie、client secret を用いる一方、PKCE を送らない。state はログイン CSRF を防ぐ別の仕組みであり、PKCE は認可コードをそのログイン開始時に生成した verifier に結び付け、コードの傍受・すり替え時の悪用を難しくする追加防御である。現在のローカルデモに実際の攻撃成立を確認したという意味ではない。

本変更ではログイン開始ごとにランダムな verifier をサーバー側の一時 state とともに保持し、SHA-256 の base64url challenge と `S256` を認可 URL に付け、token 交換時に verifier を送る。state は従来どおり一度使用すると削除する。既存 `server/auth.test.mjs` のモック GitHub に challenge/verifier の一致・欠落時拒否、意図的な不一致時のセッション未発行、state 再利用拒否を統合した。実 OAuth grant、アプリ登録、資格情報発行は行っていない。

最小の判断事項と推奨: **#9 は保留し、mock と実送金無効を維持**する。理由は法域・事業者条件・資産管理責任と、紛争・返金・誤送金の責任ルールが未確定だから。対象法域と資金の流れ、検収/異議/返金の責任者、事業者条件と専門レビューの出典・担当者・日付を揃えてから可能/保留/不可を記録する。**#10 の公開運用判断も保留**する。理由は合成 DB の復元以外の監視、問い合わせ、停止・ロールバック、個人情報対応と運用責任者のチェックが未収集だから。公開の判断は実送金を自動承認しない。
